# 두 게임 선택과 플랫포머 샘플

이 문서는 `Sample` 브랜치에 추가한 게임을 설명합니다. 빌드와 기기 실행은 아직 확인하지 않았습니다.

## 앱을 실행하면

`MainActivity`에는 슈팅게임 샘플과 플랫포머 샘플의 입장 버튼만 있습니다.

- 슈팅게임 샘플: `ShooterActivity`에서 기존 시작 메뉴, 슈팅 플레이, 게임오버, 리더보드로 이어집니다. 기존 `MainActivity`에 있던 슈팅 화면 전체를 이 Activity로 옮겼습니다.
- 플랫포머 샘플: `PlatformerActivity`에서 새 코스를 바로 시작합니다.
- Android 뒤로 가기를 누르면 선택 화면으로 돌아갑니다. 게임 안에는 게임 선택·화면 방향 전환 버튼을 두지 않습니다.

슈팅의 `ShooterScene`, Player, Bullet, Enemy, GameSession, 점수 저장과 사운드 코드는 그대로 사용합니다. 화면에 게임을 그리는 영역과 터치 좌표는 같은 화면 비율을 기준으로 계산합니다.

## 모바일 조작

게임 화면 위에 반투명 원형 조작 버튼 세 개를 겹쳐 그립니다. 왼쪽 아래에 `◀`·`▶`, 오른쪽 아래에 점프용 `▲`가 있습니다. 별도의 아래쪽 버튼 영역을 만들지 않아 게임 화면을 줄이지 않습니다. 이동 버튼을 누른 채 다른 손으로 점프할 수 있습니다. 좌우를 동시에 누르면 이동 입력은 0이 되어 감속합니다.

조작은 좌우 이동과 점프뿐입니다. 적은 머리를 밟아서 처리합니다. 버튼 밖을 터치해도 게임 동작은 일어나지 않습니다. 손가락 ID마다 어느 버튼을 누르고 있는지 따로 기록합니다.

버튼에서 손을 떼거나 손가락이 버튼 밖으로 나가면 해당 입력을 끕니다. 화면 방향 변경, 다른 앱으로 이동, 창의 포커스가 사라질 때도 입력을 지워 이동이 계속 남지 않게 했습니다.

기존 `BuildConfig.DEBUG_BLOCK`이 켜져 있을 때만 오른쪽 위에 실습용 아이콘을 표시합니다. `↻`는 처음부터 다시 시작, `⇆`는 발판 따라가기 켜기·끄기, `□`는 충돌 영역 보기입니다. 켜진 기능은 연두색으로 표시합니다. `DEBUG_BLOCK`이 꺼져 있으면 버튼을 만들지 않고 충돌 선도 그리지 않습니다. 값은 기존 `app/build.gradle.kts`의 설정을 사용하며 Release에서는 꺼집니다. `DebugConfig.SHOW_COLLIDER`는 디버그가 켜진 상태에서 충돌 선을 처음부터 표시할지 정합니다.

진행 방법을 설명하는 문구는 게임 화면에 넣지 않습니다. HUD는 체력·점수·아이템 수만 표시하고, 도착하면 FINISH를 표시합니다. FINISH를 누르면 플랫포머 화면을 닫고 로비인 게임 선택 화면으로 돌아갑니다.

## 3개 구역

게임에서 정한 길이 단위로 한 화면은 가로 16칸, 전체 맵은 가로 48칸입니다. 세로 범위는 기기 화면 비율에 맞춰 바꿉니다. 가로 16:9 화면에서는 세로 9칸이고, 더 넓은 가로 화면에서는 세로로 보이는 범위가 조금 줄어듭니다. 카메라는 캐릭터를 따라가되 맵 양 끝을 넘지 않습니다.

| 구역 | 가로 위치 | 구성 |
|---|---|---|
| 1 | 0..16 | 작은 구덩이, 높이가 다른 고정 발판, 사과·도토리. 적 없이 점프를 익히는 구역 |
| 2 | 16..32 | 18..30에 바닥이 없는 큰 구덩이. 폭 3.2칸의 나무 발판이 좌우로 이동 |
| 3 | 32..48 | 계단형 발판, 작은 이동 발판과 구덩이, 고양이·뱀, 피니시 |

두 번째 구역의 큰 발판 중심은 x=19.3..28.7 사이를 12초에 한 번 왕복합니다. 양 끝에서 바닥 가장자리에 조금 겹치므로 점프로 올라타고 반대편으로 내릴 수 있습니다. 현재 설정의 평지 점프 거리는 대략 4.1칸이므로 12칸짜리 구덩이를 점프 한 번으로 건널 수 없습니다.

피니시에는 사과와 도토리 45개를 여러 줄로 쌓았습니다. 위치와 회전을 조금씩 다르게 해서 아이템 더미처럼 보이게 했습니다. 길을 안내하는 아이템 11개도 따로 있습니다. 사과는 10점, 도토리는 20점입니다. x=46.2 이후 바닥에 도착하면 완료 문구가 뜹니다. 모든 아이템을 모아야 하는 조건은 없습니다.

작은 깃발이 있는 두 번째·세 번째 구역 입구에 도착하면 다시 시작할 위치를 갱신합니다. 추락하거나 체력을 모두 잃으면 납작하게 울먹이는 동작을 보여 준 뒤 해당 구역 입구에서 체력 3으로 다시 시작합니다. 오른쪽 위의 `↻`는 점수·아이템·적 상태까지 처음으로 되돌립니다.

## 발판과 캐릭터가 움직이는 순서

`PlatformerScene.update()`가 `DigitalInput.drain()`으로 입력을 읽고 `PlatformerWorld.update()`에 전달합니다. 화면을 그리는 프레임의 시간을 최대 1/120초씩 나누어 아래 계산을 반복합니다.

1. 모든 발판의 새 위치와 이전 위치의 차이를 구합니다.
2. 이전에 서 있던 발판을 확인합니다. 점프하면 그 발판을 떠납니다.
3. 계속 서 있으면 발판 이동량을 캐릭터 위치에 한 번 더합니다.
4. 입력에 따른 가속·감속과 가로 충돌을 계산합니다.
5. 중력을 적용하고 세로 충돌을 계산해 새로 서 있는 발판을 기록합니다.
6. 적의 이동, 머리 밟기, 몸통 피격, 아이템, 추락과 피니시를 확인합니다.
7. `PlatformerPainter`가 계산된 위치에 배경·발판·아이템·적·캐릭터를 그립니다.

`⇆`를 눌러 발판 따라가기를 끄면 3번을 건너뜁니다. 캐릭터가 제자리에 있는 동안 발판만 움직여 결국 가장자리에서 떨어지는 상황을 비교할 수 있습니다. 발판에서 내려오거나 점프한 뒤에는 발판 이동량을 계속 더하지 않습니다. 발판에서 떠날 때 발판의 속도를 캐릭터에게 더하는 동작은 넣지 않았습니다.

## 적의 머리 밟기와 몸통 접촉

고양이와 뱀은 머리를 제대로 밟으면 한 번에 처리합니다. 고양이는 100점, 뱀은 150점입니다. 두 적 모두 이동 애니메이션만 사용하며 적의 체력 막대는 표시하지 않습니다.

머리 밟기는 캐릭터가 내려오는 중이고, 이전 발바닥이 머리 위에 있었으며, 이번 이동에서 머리 윗면을 지나간 경우에만 유효합니다. 고양이 몸통에 닿거나 뱀의 몸·꼬리를 밟으면 플레이어가 피해를 받습니다. 머리 밟기에 성공한 계산에서는 몸통 피해를 함께 주지 않습니다. 적이 반대쪽을 볼 때는 그림과 머리 위치를 함께 뒤집습니다.

기존 슈팅은 `Bullet`을 만들어 이동시키고, 충돌하거나 화면 밖으로 나가면 없앱니다. 플랫포머는 이동·점프·머리 밟기로 진행합니다.

## 학생이 바꿔 볼 값

`foundation/physics/KinematicMotor.kt`의 `MotorSettings`에서 가속도 24, 감속도 30, 최대 속도 5, 중력 22, 점프 시작 속도 9를 바꿀 수 있습니다. 속도는 위치가 변하는 빠르기이고, 가속도는 그 속도가 변하는 빠르기입니다. 계산에는 초 단위 deltaTime을 사용합니다. 현재 가로 속도는 `player.velocityX`로 확인합니다.

`PlatformerLevel.kt`에서는 발판 위치·폭·왕복 시간, 구덩이 폭, 적의 이동 구간, 아이템 더미 위치를 바꿀 수 있습니다. 빠른 물체의 지형 통과, 경사면, 발판 사이에 끼이는 상황은 추가 구현이 필요한 부분입니다.

## 화면 방향과 좌표

방향은 `AndroidManifest.xml`에서 `ShooterActivity`를 portrait, `PlatformerActivity`를 landscape로 고정합니다. 게임 안에 방향 전환 버튼은 없습니다. 두 게임 모두 상태 표시줄과 내비게이션 바를 숨깁니다.

슈팅은 기존 9:16 비율을 기준으로 `FitViewport`를 사용합니다. 플랫포머는 `glViewport(0, 0, width, height)`로 화면 전체를 사용합니다. `Scene.resize()`에서 `viewHeight = 16 × 화면 높이 / 화면 너비`를 계산하고 그리기에 적용합니다. 캐릭터와 충돌 도형의 크기를 유지하면서 세로 표시 범위만 바꾸므로 그림이 가로로 늘어나지 않습니다.

플랫포머는 `PlatformerControlsView`에서 화면 위에 버튼을 그리고 터치 위치를 읽습니다. 카메라 구멍과 시스템 바 위치는 조작부 여백에만 반영하며 게임 화면 자체는 줄이지 않습니다.

## 코드 위치

`app/src/main/java/kr/ac/lecture/mobilegame/` 기준입니다.

| 파일 | 역할 |
|---|---|
| `MainActivity.kt` | 두 게임 입장 화면 |
| `ShooterActivity.kt` | 기존 슈팅 전체 화면과 메뉴 |
| `PlatformerActivity.kt` | 전체 화면, HUD와 아이콘 배치, Android 연결 |
| `game/platformer/PlatformerControlsView.kt` | 화면 위의 ◀·▶·▲ 그리기와 손가락별 버튼 입력 |
| `foundation/core/SceneSurfaceView.kt` | 플랫포머의 GL 생성·재개·일시정지·Update/Render 호출 |
| `game/platformer/PlatformerScene.kt` | 입력, 게임 계산, HUD, 그리기 연결 |
| `game/platformer/PlatformerLevel.kt` | 세 구역과 발판·아이템·적 배치 |
| `game/platformer/PlatformerWorld.kt` | 이동, 밟기, 점수, 사망·재시작·피니시 |
| `game/platformer/PlatformEnemy.kt` | 두 적의 이동과 머리·몸통 충돌 범위 |
| `game/platformer/PlatformerSprites.kt` | 스프라이트 시트와 발 위치, 발판의 투명 여백 처리 |
| `game/platformer/PlatformerPainter.kt` | 카메라 좌표 변환과 그림 출력 |

그림만 바꾸려면 `PlatformerSprites`와 `PlatformerPainter`를 수정합니다. `PlatformBody`와 적의 충돌 크기는 별도로 유지합니다. 플랫포머만 도트용 `GL_NEAREST` 필터를 사용하고 슈팅은 기존 `GL_LINEAR`를 유지합니다.

## 직접 실행할 때 확인할 순서

1. 앱 시작 화면의 두 버튼이 각각 해당 게임을 여는지 확인합니다.
2. 슈팅의 시작·터치 이동·자동 발사·폭탄·보스·게임오버·리더보드를 확인합니다.
3. 플랫포머에서 좌우 이동, 손 떼기, 이동 중 점프를 확인합니다. 버튼 밖을 눌렀을 때는 동작이 없어야 합니다.
4. 첫 구역에서 작은 구덩이를 건너고, 두 번째 구역에서 이동 발판에 올라타 기다리거나 걸어 봅니다.
5. 따라가기 ON/OFF, 점프로 발판 떠나기, 반대편 바닥에 내리기, 추락 후 재시작을 비교합니다.
6. 세 번째 구역에서 고양이·뱀의 머리를 밟아 처리합니다. 뱀의 몸통을 밟았을 때는 피해를 받는지 확인합니다.
7. 아이템 더미와 피니시, 처음부터 다시 시작을 확인합니다.
8. 슈팅은 세로, 플랫포머는 가로로 열리는지 확인합니다. 플랫포머가 여백 없이 채워지는지, 다른 앱을 열었다 돌아와도 입력이 남지 않는지, Android 뒤로 가기로 게임 선택 화면에 돌아갈 수 있는지 확인합니다.

이번 변경에서는 테스트 파일을 추가하거나 빌드·기기 실행·Git 커밋을 진행하지 않았습니다. 실제 동작 확인은 위 순서로 진행하면 됩니다.
