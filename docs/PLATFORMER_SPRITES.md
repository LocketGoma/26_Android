# 플랫포머 도트 리소스

참고 캐릭터의 크림색 몸, 갈색 눈, 작은 분홍 코, 큰 줄무늬 꼬리를 사용했습니다. 사망은 밀대 없이 납작해져 울먹이는 동작입니다. 배경은 옅은 풀숲 실루엣으로 단순화했고, 지면과 공중 발판의 평평한 윗면이 눈에 띄도록 색을 구분했습니다.

스프라이트 제작을 마쳤습니다. 게임에 그림을 연결하거나 밟기 판정을 추가하는 작업은 아직 하지 않았습니다. 빌드와 Git 커밋도 진행하지 않았습니다.

## 파일과 재생 순서

PNG 위치: `app/src/main/res/drawable-nodpi/`. 각 시트의 그림 번호는 왼쪽 위부터 오른쪽으로 매기고, 다음 줄로 이어집니다. 배경을 제외한 PNG의 빈 부분은 투명합니다.

| 파일 | 격자 | 내용 | 권장 재생 |
|---|---|---|---|
| `platformer_player_idle.png` | 2×2 | 숨쉬기·꼬리 움직임 4프레임 | 5 FPS, 반복 |
| `platformer_player_run.png` | 2×2 | 좌우 발이 교차하는 이동 4프레임 | 10 FPS, 반복 |
| `platformer_player_jump.png` | 2×2 | 웅크림, 상승, 정점, 하강 | 실제 점프 상태에 맞춰 선택 |
| `platformer_player_hurt.png` | 2×2 | 놀람, 움찔, 웅크림, 회복 | 10 FPS, 한 번 |
| `platformer_player_death.png` | 2×2 | 눈물, 몸 낮춤, 납작해짐, 울먹임 유지 | 6 FPS, 한 번 후 마지막 유지 |
| `platformer_enemy_cat_walk.png` | 2×2 | 주황 고양이 이동 4프레임 | 8 FPS, 반복 |
| `platformer_enemy_snake_slither.png` | 2×2 | 초록 뱀의 기어가기 4프레임 | 7 FPS, 반복 |
| `platformer_items.png` | 2×1 | 0: 사과, 1: 도토리 | 고정 이미지 |
| `platformer_platforms.png` | 1×2 | 0: 초록 잔디·흙 지면, 1: 황금빛 나무 발판 | 고정 이미지 |
| `platformer_background_grass.png` | 1×1 | 채도·대비가 낮은 간단한 풀숲 배경 | 화면 또는 먼 배경 레이어 |

플레이어와 고양이의 한 프레임은 정사각형입니다. 뱀은 가로가 세로의 두 배입니다. 게임에서 플레이어·고양이는 가로 1칸·세로 1칸, 뱀은 가로 2칸·세로 1칸을 기준으로 배치합니다. 아이템은 그보다 작게 그립니다. 원본 PNG는 큰 크기로 만든 도트 스타일 이미지입니다. 실제 픽셀 수를 32×32 또는 64×64로 줄인 파일은 아닙니다. `manifest.json`의 `logicalDisplaySize`는 화면에 표시할 때 권장하는 크기입니다.

원본 크기, 각 프레임의 텍스처 좌표(UV), 그림이 차지하는 범위, 권장 FPS, 파일 확인용 SHA-256 값은 `assets/platformer/manifest.json`에 있습니다. 투명 여백은 충돌 크기에 포함하지 않습니다. 뱀 원본 높이가 홀수여서 프레임 높이는 443.5px입니다. PNG를 정수 픽셀 단위로 잘라내지 않고 UV로 나누어 읽으면 기존 `SpriteSheet`의 소수점 크기 계산을 그대로 사용할 수 있습니다.

## Android 연결 위치

기존 `foundation/graphics/sprite/SpriteSheet.kt`를 그대로 사용할 수 있습니다. 예를 들어 플레이어 시트를 `SpriteSheet(resources.texture(R.drawable.platformer_player_idle), 2, 2)`로 읽고, `region(index % 2, index / 2)`로 순서대로 선택합니다. 이 예제는 연결 방법 설명이며 게임에 적용한 코드는 아닙니다.

`foundation/graphics/ResourceManager.kt`는 현재 모든 텍스처에 `GL_LINEAR`를 사용합니다. 도트가 흐려지지 않도록 향후 플랫포머 리소스에 한해 `GL_NEAREST`를 선택할 수 있게 확장하는 편이 좋습니다. 기존 슈팅의 필터를 일괄 변경하지 않습니다. 이미지의 왼쪽 보기에는 UV 좌우 반전을 사용하면 됩니다.

Render는 동작에 맞는 Sprite 프레임을 골라 캐릭터의 발 위치에 맞춰 그립니다. 이동·충돌은 `PlatformBody`에서 따로 계산합니다. `visibleBoundsInCell`의 아래쪽 값을 사용하면 그림 속 발바닥을 발판 높이에 맞출 수 있습니다. 사망할 때 그림이 납작해져도 충돌 크기는 자동으로 줄이지 않습니다. 사망 상태에서 충돌을 끌지는 게임 규칙으로 정합니다.

## 적을 밟았는지 확인하는 방법

고양이와 뱀에는 이동 프레임만 있습니다. 공격·피격·사망 애니메이션은 추가하지 않았습니다. 게임에 연결할 때는 다음과 같이 처리합니다.

- 고양이: 머리 위에 내려앉을 때 유효한 밟기로 처리합니다. 옆구리와 몸통 접촉은 플레이어 피격입니다.
- 뱀: 오른쪽에 들린 둥근 머리만 밟을 수 있습니다. 길게 이어진 몸과 꼬리를 위에서 밟아도 플레이어 피격입니다.
- 그림이 겹쳤다는 이유만으로 밟았다고 처리하지 않습니다. 캐릭터가 떨어지는 중인지, 이전 발바닥이 적의 머리보다 위였는지, 이번 이동에서 머리 윗면을 지나갔는지, 가로 범위가 겹치는지를 함께 확인합니다.
- 머리를 제대로 밟았다면 같은 계산에서 몸통에 닿았다고 피해를 주지 않습니다. 밟은 뒤 얼마나 튕겨 오를지, 적을 언제 없앨지는 각 게임에서 정합니다.
- 왼쪽을 보게 뒤집을 때는 그림과 머리 충돌 영역의 X 위치를 함께 뒤집습니다. 애니메이션이 조금 바뀔 때마다 충돌 범위가 흔들리지 않도록 머리·몸통의 충돌 도형은 고정된 크기를 사용합니다.

`assets/platformer/preview.html`에서 발판·캐릭터·아이템 배치와 각 애니메이션을 볼 수 있습니다. 그림의 배치와 움직임을 확인하는 미리보기이며 게임의 이동·충돌 계산은 실행하지 않습니다. 점프도 여기서는 그림을 순서대로 보여 줍니다. 실제 게임에서는 상승·정점·하강 상태에 맞춰 프레임을 고릅니다.

## 배경과 발판

풀숲 배경에는 충돌 영역을 두지 않습니다. 잔디 지면과 나무 발판은 배경보다 앞에 따로 그립니다. 발판 PNG의 투명 여백을 제외한 윗면을 충돌 영역의 윗면에 맞춥니다. 나무 발판 그림은 고정 발판과 움직이는 발판에 모두 사용할 수 있습니다. 움직이는 발판은 `PlatformSurface`의 위치를 바꾸어 표현합니다.

두 발판은 긴 사각형 한 장으로 만든 Sprite입니다. 여러 장을 이어 붙이도록 만든 타일은 아닙니다. 발판 폭을 크게 바꾸려면 왼쪽 끝·가운데·오른쪽 끝 그림을 따로 만들고 가운데만 반복해서 그리는 방법을 추가로 실습할 수 있습니다.

## 생성·확인 기록

내장 `image_gen` 도구로 만들었고 선택한 PNG를 픽셀 변경 없이 저장했습니다. 생성 프롬프트는 `assets/platformer/generation_prompts.json`에 남겼습니다. 프롬프트 파일은 `.gitignore`에 등록해 이 컴퓨터에만 보관하고 Git 커밋에는 포함하지 않습니다. 참고 원본은 저장소에 복사하지 않았습니다.

최종 PNG 10개를 눈으로 확인하고, 파일 크기·색상 모드·투명도·시트 비율·빈 프레임 여부도 확인했습니다. Android 빌드와 기기 실행은 사용자가 직접 진행하기로 해 실행하지 않았습니다. 게임에 연결한 뒤의 화면과 충돌 동작은 아직 확인하지 않았습니다.
